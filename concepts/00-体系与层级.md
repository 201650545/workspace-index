# 00 · 体系与层级

## 三个最重要的"不等号"（所有 Agent 强制记住）

1. **Vault ≠ Git 仓库**
   Vault 是 Obsidian 的浏览/知识工作空间；Git 仓库是版本、权限、历史和发布边界。
2. **项目 ≠ 文件夹**
   "项目"是责任和生命周期概念；文件夹只是物理承载方式。
3. **数据源 ≠ 项目**
   飞书 Base、JSON、API、资产清单等可以服务项目，但不会因此自动成为 workspace-index 的项目。

## 三个维度不是同义词

以逆天主题为例，三个身份同时成立但不互相等价：

```
D:\Work\逆天主题
├─ Obsidian 身份：Work Vault 内的子库
├─ Git 身份：独立仓 nitian-theme
└─ 业务身份：逆天主题游戏项目
```

"子库""仓库""项目"是三个维度。

## Vault 层

### Work（工作库）— `D:\Work`
- **是什么**：所有"要长期维护、要协作、要版本化"的工作知识的联合浏览区；不是单一真源，而是四个独立真源（子库文件夹）的物理容器。
- **干什么**：给人/外部 AI 找"跟项目有关的一切"；搜索空间覆盖四个子库。
- **边界**：Work 根**不是 git 仓**（不给 Work 建大仓）；每个子库各自独立 `.git`，互不嵌套提交；记忆（私人/信息化）不许进 Work。
- **真源**：无"Work 级"真源；真源在各子库。Work 只提供目录外壳 + `项目索引/concepts/` 这张地图。

### Memory（记忆库）— `D:\记忆`
- **是什么**：跨 Agent、跨会话保存持续状态、决策和协作记忆的独立生命周期边界；也是 Claude 调度大脑人读记忆镜像。
- **干什么**：让不同 Agent 在换模型、换窗口、换执行者后恢复项目状态与既有决策。
- **边界**：不保存业务项目完整正文；不代替项目仓；不承担 Workspace 路由；不把飞书当记忆正文源。
- **真源**：本地运行边界 `D:\记忆`；Git 运行仓 `ai-hub-memory`；概念定义 `concepts/30-Memory.md`。

## 进 projects.yaml 的判定规则

某样东西**同时满足以下条件**才进入（"项目"是宽义一级工作单元，不等于狭义产品项目）：

1. 是 Workspace 的一级责任单元，不是另一个项目内部的模块或资源。
2. 有独立 Git 仓库 / 版本生命周期。
3. 有稳定入口（README / project.yaml）。
4. 外部 Agent 有合理场景需要直接路由进入它。

**一句机械判定**：
> 能否作为一个独立 Git 仓被陌生 Agent 直接进入，并且进入后存在自己的一套事实 / 规范 / 生命周期？能，则进；不能，则不进。

所以 handbook 虽不是产品可进、Memory 虽不是产品可进——关键不是"是不是产品"，而是**是不是一级、独立、稳定、可路由的版本边界**。
