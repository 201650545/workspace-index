# 概念模板 · v2（六字段 + 文件/目录用途 + 三真源 + 冲突裁决 + 粒度宪法）

三类条目共用本模板，但每类只填属于自己的字段，**不加路径和模板字段以外的内容**：

- **A. 概念条目**（`common-concepts.md` 等）：填六字段。
- **B. 项目条目**（`projects/*.md`）：基本定义六字段 + 路由入口 + 核心模块地图 + 不展开内容 + 关键路径文件用途。
- **C. 文件/目录用途**：只填 路径 / 层级 / 一句话用途 / 负责 / 不负责 / 真源。

---

## A. 六字段标准模板

```
## <Concept ID> · <名称>

- **名称 Name**：
- **层级 Level**：Vault / 项目 / 仓库 / 子库 / 子模块 / 支撑目录 / 文件 / 外部数据层
- **是什么（一锤定音）**：
- **干什么**：
- **边界（不干什么）**：
- **真源在哪**：
```

## C. 文件 / 目录用途模板（GPT v2 标准）

字段 = `路径` | `层级（支撑目录/子模块/核心模块）` | `一句话用途` | `负责` | `不负责` | `真源`。层级分两种：**支撑目录**（服务他人，非业务本体）与**核心模块**（承载业务职责）。

---

## 三真源（互不越权）

| 真源 | 独管 |
|---|---|
| `projects.yaml` | **WHERE** —— 有哪些一级项目、去哪找 |
| `concepts/` | **WHAT / NOT WHAT** —— 它是什么、它不是什么 |
| 各项目 Owner 仓 README/docs | **FACT** —— 它现在真实是什么 |

**原则**：解释器拥有"这个词是什么意思"的最终解释权，但**不拥有**"这个东西当前运行成什么样"的事实。**禁止双写**——concepts 不复制项目列表、状态、URL 清单（status/repo/task_board 属于 projects.yaml）。

## 冲突裁决顺序

按"问题类型"裁决，而不是规定某个文件永远最大：

| 问题 | 最终真源 |
|---|---|
| 这个概念是什么意思 / 边界在哪？ | workspace-index/concepts/ |
| 有哪些一级项目 / 仓？去哪找？ | workspace-index/projects.yaml |
| 该项目现在实际是什么状态？ | 对应项目仓 README / Home / docs / Owner |
| 这个模块具体怎么运行？ | 模块 README + 实现/配置 |
| 所有项目默认应遵守什么？ | handbook，项目 override 优先 |
| Agent 当前记忆、决策、状态？ | Memory / ai-hub-memory 运行仓 |
| 飞书里现在有什么结构化记录？ | 对应飞书 Base / 导出数据层 |

## 粒度宪法三问（决定一个文件/路径要不要写进 concepts）

对每个候选路径依次问，三个都指向"写"才写：

1. **外部 Agent 会不会迷路？** —— 不写它，陌生 Agent 是否无从判断这是个什么、从哪读？会迷路 → 写。
2. **删除后是否需要重新猜职责？** —— 删掉这一行/文件，后来者是不是要重新猜测该路径的用途才敢动？需要猜 → 写。
3. **是否已在 README/docs 有详细内容？** —— 已有详细说明 → 只保留"它是什么 + 去哪看"，不复制正文。

**绝不写**：为什么存在 / 设计原因 / 历史演进 / 未来规划 / 实现细节（这些指向各项目 docs）。

## 范围闸门（写文件/目录用途时跳过）

跳过：普通业务代码、测试文件、临时脚本、图片/资产文件、历史归档、非结构化随手笔记。
