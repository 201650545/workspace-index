# 10 · 项目与仓库

## Q1 · 「项目索引」到底索引什么

**一锤定音**："项目索引"不是所有文件、资源和数据源的目录；它是**"工作空间一级、可独立路由的 Git 版本单元"的注册表**。

"项目"是宽义一级工作单元，不等于狭义产品项目。handbook 不是产品也可以进，Memory 不是产品也可以进——关键不是"是不是产品"，而是**是不是一级、独立、稳定、可路由的版本边界**。

**判定规则**：见 `00-体系与层级.md` →「进 projects.yaml 的判定规则」+ 机械判定句。

**几个明确结论**：
- ✅ **逆天主题 / handbook / ai-platform / ai-hub-memory** 都进（见判定表）。
- ❌ **飞书多维表格**：是结构化数据层/数据源，不是 Workspace 一级项目路由单元。可被某项目引用，也可在 `integrations/feishu/` 内拥有数据 catalog，但那个 catalog 里的 "project" 只是数据导出 namespace，不是一级项目。地址：`❌ projects.yaml`。
- ❌ **本地补项目 / 临时项目（没开 GitHub 仓）**：暂时不进。仍可存在于 Work，但正式"升格"为一级工作单元前不入公共路由真源。升格链：临时目录 → 明确长期职责 → 建独立仓 → README/project.yaml → 才登记。否则公共索引会出现外部 AI 无法访问的 `D:\...` 路由。
- ❌ **本地随便笔记**：绝对不进。普通笔记是知识内容，不是路由节点。

## Q2 · 「逆天主题」要不要进项目索引

**要，而且现在这一行是正确的，不得删除。** 原因不是"位于 D:\Work 下"，而是它同时满足：
- 独立业务目标：一个《仙逆》深度联动修仙养成网页游戏。
- 独立 Git 仓：nitian-theme。
- 独立项目事实：docs/00-项目总览.md。
- 独立任务、资产、规格体系 + 独立生命周期 + 外部 Agent 有直接进入的必要。

它有三种同时成立但不互等的身份：Obsidian 子库（`D:\Work\逆天主题`）、Git 仓（nitian-theme）、业务项目（逆天主题游戏）。

## 六字段样板 · 逆天主题

### nitian-theme · 逆天主题（仙逆）游戏
- **名称 Name**：逆天主题（nitian-theme）
- **层级 Level**：项目 / 仓库；在 Work Vault 中同时表现为一个子库文件夹。
- **是什么（一锤定音）**：一个独立的《仙逆》深度联动修仙养成网页游戏项目；nitian-theme 是它的 Git 版本边界。
- **干什么**：保存该游戏自己的设计、任务、规格、资产台账以及生产/校验工具，形成"当前真实是什么"的项目事实源。README 明确指向 docs/00、任务看板、资产清单和项目规格作为 Source of Truth。
- **边界（不干什么）**：不保存跨项目通用规范；不承担 Workspace 路由；不管理 AI 基础设施；不承担多 Agent 运行记忆；成品图片、视频、GLB 也不因为属于游戏就进入 Git 仓。
- **真源在哪**：
  - 概念定义：`concepts/10-项目与仓库.md#nitian-theme`
  - 项目路由：`projects.yaml → id: nitian-theme`
  - 项目事实：`nitian-theme/README.md → docs/00-项目总览.md`
  - 任务：`docs/01-任务看板.md` ｜ 资产：`docs/02-资产清单.md` ｜ 项目规格：`docs/03-规格与规范.md`
  - 通用规范：引用 handbook
