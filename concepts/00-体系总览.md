# 00 · 体系总览

> Workspace = Work Vault + Memory Vault 的整体骨架。本页解答"整个体系有哪些层级、谁管哪一层"。

## 一句话

```
Workspace = Work Vault + Memory Vault

Work Vault:  通用规范(handbook) · 项目索引(workspace-index) · 逆天主题(nitian-theme) · AI平台(ai-platform)
Memory Vault: Agent 持续记忆（运行仓 ai-hub-memory）

飞书：不在此图内（外部数据层，见 common-concepts）
```

## 层级表

| 层级 | 代表 | 是什么 | 路由对象 |
|---|---|---|---|
| **Vault** | Work Vault / Memory Vault | Obsidian 浏览/知识工作空间（容器） | 不直接路由（非 Git 项目） |
| **仓库** | handbook / workspace-index / nitian-theme / ai-platform / ai-hub-memory | 版本、权限、历史、发布边界 | 是 |
| **项目** | nitian-theme / ai-platform / handbook / ai-hub-memory | 责任与生命周期单元（宽义一级工作单元） | 是 |
| **子库** | Work Vault 内各业务文件夹 | Obsidian 侧文件夹承载某仓 | 否 |
| **子模块** | resource-ops / integrations/feishu / agent/memory / global / projects/<id> | 项目内部正式模块 | 否 |
| **支撑目录** | config / docs / tests / scripts | 服务他人，非业务本体 | 否 |
| **文件** | STATE / DECISIONS / CHANGELOG / projects.yaml | 记忆类型或路由表 | 数据对象 |
| **外部数据层** | 飞书多维表格 Base / JSON / API | 结构化数据源 | 否 |

## 五个仓库的真实分工

| 仓 | dominant 职责 | 管什么 | 不管什么 |
|---|---|---|---|
| workspace-index | 工作空间元数据控制层 | WHERE(projects.yaml) + WHAT/not-WHAT(concepts) | 不存任何项目正文副本 |
| handbook | 通用规范 | 所有项目默认应该怎么做 | 不描述 Workspace 有哪些实体 |
| nitian-theme | 业务项目 | 逆天主题游戏自身的项目事实 | 不承担跨项目规范/路由/AI 基建 |
| ai-platform | AI 基建主仓 | 平台主干/资源运营/飞书桥/记忆协议快照 | 不是业务正文仓、不是运行记忆库 |
| ai-hub-memory | 运行记忆仓 | 跨 Agent 跨会话持续状态/决策/历史 | 不存业务项目完整正文 |

## 三真源（互不越权）

- `projects.yaml` —— **WHERE**：有哪些一级项目、去哪找。
- `concepts/`（本目录）—— **WHAT / NOT WHAT**：它是什么、它不是什么。
- 各项目 Owner 仓 —— **FACT**：它现在真实是什么。

## 一句话总宪法

> **projects.yaml 决定"去哪"；concepts 决定"它是什么、它不是什么"；项目仓决定"它现在真实是什么"；handbook 决定"默认应该怎么做"；Memory 决定"我们之前做过什么、现在接着哪里做"；飞书只提供结构化数据。**
>
> 这六句话互不越权，整个体系就不会再靠猜。

## 三个最重要的"不等号"（所有 Agent 强制记住）

- **Vault ≠ Git 仓库**：Vault 是 Obsidian 的浏览/知识工作空间；仓库是版本、权限、历史和发布边界。
- **项目 ≠ 文件夹**：项目是责任和生命周期概念；文件夹只是物理承载方式。
- **数据源 ≠ 项目**：飞书 Base、JSON、API、资产清单可以服务项目，但不会因此自动成为一级项目。
