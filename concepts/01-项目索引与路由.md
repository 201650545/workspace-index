# 01 · 项目索引与路由

> 说明 `projects.yaml`（WHERE 真源）到底索引什么、不索引什么。本页只解释"边界"，不复制项目列表本身（列表真源在 projects.yaml）。

## 一锤定音

> **"项目索引"不是所有文件、资源和数据源的目录；它是"工作空间一级、可独立路由的 Git 版本单元"的注册表。**

这里的"项目"是**宽义一级工作单元**，不等于狭义产品项目。所以 handbook（不是产品）可以进，Memory（不是产品）也可以进。关键不是"是不是产品"，而是它是不是一级、独立、稳定、可路由的**版本边界**。

## 进入 projects.yaml 的判定规则

同时满足以下条件才进入：

1. 是 Workspace 的一级责任单元，不是另一个项目内部的模块或资源。
2. 有独立 Git 仓库 / 版本生命周期。
3. 有稳定入口（README / project.yaml）。
4. 外部 Agent 有合理场景需要直接路由进入它。

**一句机械判定**：
> 能否作为一个独立 Git 仓被陌生 Agent 直接进入，并且进入后存在自己的一套事实/规范/生命周期？能，则进；不能，则不进。

## 本地项目的升格条件

临时目录 无 GitHub 仓 → 暂时不进。升格路径：

```
临时目录 → 明确长期职责 → 建独立仓 → README/project.yaml → 才登记 projects.yaml
```

否则公共 GitHub 索引会出现一个外部 AI 根本无法访问的 `D:\...` 路由，失去意义。
